## 4. 修正後のモニター課題

### 初日

1. 呼び名、関係、都道府県、市区町村を入力して手帳を1冊作る。
2. クラウド保存は任意。端末故障などに備えたい人だけ「手帳データの保存先」からメール確認する。
3. クラウド保存の有無にかかわらず、以後7日間は同じスマートフォン・同じブラウザを使う。プライベートブラウズ、履歴・サイトデータ削除は禁止。

### 7日間

1. 1日1回「今日の記録」を保存する。ただし未達でも最終回答を閉じない。
2. 保存した過去の記録を見返す。
3. 確認リスト、書類の所在メモ、AI相談を各1回試す。
4. 家族招待画面を開いて手順を確認する。招待送信は任意。

### 8日目

1. 0:00以降に手帳上部の最終回答案内を開く。
2. 15〜20分のアンケートへ回答する。
3. 気になった画面のスクリーンショットを1〜3枚添付する。

報酬2,000円は最終回答の提出で支払う。日記中断、機能未達、否定回答で減額しない。

## 5. カレンダー日gate

- `startedAt` のローカル年月日を開始日=1日目とする。
- 開始日の7日後、0:00を `reportDueAt` とする。
- 例: 8月25日11:00開始なら、9月1日0:00に開く。
- 回答画面には具体的な開放日と0:00を表示する。
- 日記回数や機能到達はgateにしない。
- `?preview=1` は日付制限を越えて全設問を表示するが、送信ボタンとsubmit処理の両方を止める。

## 6. 自動添付する利用状況

回答時に、プロフィールや日記本文ではなく次の数値・到達フラグだけを端末から収集する。

- モニター開始時刻、回答可能時刻、計測時刻。
- 手帳を開いた回数と実日数。
- 最初の手帳作成時刻と、開始から作成までの秒数。
- モニター期間中に端末へ保存された日記件数と日付数。
- 「今日の記録」保存ボタンを押した回数、保存した実日数、最後に保存したモニター日。
- 確認リストで変更された項目数。
- 過去記録を開いたか。
- 確認リストを開いたか。
- 書類の所在メモを保存したか。
- 家族招待画面を開いたか。
- AI相談が成功したか。
- クラウド控えを確認できたか。

日記の自己申告設問は残し、自動カウントとの差も調査結果として管理画面へ表示する。自動値で回答を拒否しない。

## 7. 修正後アンケート

### 必須17項目

1. クラウドワークスで使っている名前。
2. 年代。
3. 介護や備えの対象者との関係。
4. 現在の状況。
5. 主に使った端末。
6. 何日間画面を開いたか（自己申告）。
7. 何日「今日の記録」を保存したか（自己申告）。
8. 確認リスト: 使えた / 使えなかった / 見つからなかった / 必要がなかった。
9. 書類メモ: 同上。
10. 家族招待手順: 確認できた / 分からなかった / 見つからなかった / 必要がなかった。
11. 保存した記録の再発見。
12. AI相談: 使えた / 迷ったが使えた / 使えなかった / 見つからなかった / 必要がなかった。
13. 一番最初に迷った場所（単一選択。「迷わなかった」を含む）。
14. 今後も記録に使いたいか。
15. 家族と共有したいか。
16. 価格提示前: 月いくらまで払えるか（0円 / 300円 / 500円 / 980円 / 980円以上）。
17. 実価格提示後: 月980円を払う / 年払いなら検討 / 家族と相談 / 無料範囲だけ / 使わない。

### 補足回答

- ほかに迷った場所（複数選択、任意）。
- 一番分かりにくかったところ（任意、1,000文字）。
- 一番役に立ちそうなところ（任意、1,000文字）。
- 足りない機能、使わない理由（任意、1,000文字）。
- スクリーンショット1〜3枚（JPEG / PNG / WebP、各4MB以下）。

## 8. 回答・画像・重複処理

- 回答APIは1時間5回、画像APIは1時間12回のrate limit。
- 画像前にクラウドワークス表示名だけをpreflight照合し、入力違いによる孤立画像を減らす。
- `MONITOR_ALLOWED_CROWDWORKS_NAMES` が未設定なら回答APIは503で受付を開かない。
- 許可名はNFKC正規化と小文字化で照合し、raw値は管理表示用に保存する。
- 画像pathは1〜3件だけ受け付ける。
- 回答は `audit_logs.action = monitor_feedback_submitted` に保存する。
- 同じ `crowdworksNameKey` の回答があればinsertせずmetadataを上書きし、再送回数を残す。
- 管理画面の画像は管理者認証後だけ1時間の署名URLを発行する。
- form versionは `2026-08-25-monitor-review-v2`。

## 9. 10人の結果判定

10人を大規模な統計調査として扱わず、探索的なモニターとして次の暫定基準と定性データを組み合わせて判断する。

- **前進**: 3人以上が「月980円を払って使う」または「年払いなら検討」を選び、7人以上が自動カウントで7日中5日以上記録。
- **再設計**: 7人以上が5日以上記録した一方で、上記の支払意向が2人以下。価値はあるが価格または課金対象を見直す。
- **立ち止まり**: 7人以上が3日以内に記録停止。追加機能より先に記録習慣を見直す。

どの基準にも明確に当てはまらない場合は無理に合否を作らず、10人分の定性データから再設計箇所を決める。

必ず並べる定性データ:

1. 初回登録の時間と最初の躓き。
2. 自動日記日数と自己申告の差。
3. 記録が止まった日と理由。
4. 価格提示前後の反応差。
5. スクリーンショットに共通する画面。

## 11. 残る技術的論点

- モニター開始時刻、送信済み状態、行動計測は同じブラウザのlocalStorageに残る。クラウド控えは手帳本文を守るが、この計測状態までは復元しない。
- 利用状況はクライアント計測であり、改変不可能な監査ログではない。10人の探索的テスト向けの突合材料として使う。
- 回答APIはカレンダー日gate自体をサーバー検証しない。ただし許可された10名以外は送れない。
- 回答は専用テーブルでなく `audit_logs`。6か月削除は運営表による手動管理。
- 参加者preflight後、画像保存には成功したが回答本体が失敗した場合、孤立画像が残る可能性はある。

専用研究テーブル、サーバー発行セッション、画像のトランザクション化は10人モニター後のP2とする。
