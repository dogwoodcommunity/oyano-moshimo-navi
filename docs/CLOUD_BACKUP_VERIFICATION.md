# クラウド保存・復元・家族共有の確認手順

最終更新: 2026-09-05

この文書は試験手順であり、実機試験の完了記録ではありません。ローカル試験と、認証済みの
2アカウント・2端末による実機試験は別々に記録します。既存モニターの手帳・写真・回答は使いません。
本番でのアカウント作成、メール送信、テスト記録の追加・削除は、対象と範囲を確認したうえで行います。

## 1. ローカル自動試験

依存関係がインストール済みで、実行用 `.env` / `.env.local` 等を含まないソースcheckoutから実行します。
実行環境の認証情報は渡しません。手順の表示と、ソース・疑似実行のみの試験は次のとおりです。

```bash
node scripts/test-stage-a-local.mjs --plan
node scripts/test-stage-a-local.mjs --source-only
node scripts/test-stage-a-local.mjs --sql-only
```

全ローカル試験には、非対話式lintの設定、Web/Mobileの依存関係、ローカルDockerと
取得済みの `postgres:16-bookworm` イメージが必要です。

```bash
node scripts/test-stage-a-local.mjs
```

- 固定されたソース・runtime試験、lint、型検査、破棄専用PostgreSQL回帰9本、Web buildを順番に実行します。
- pnpmの自動installを防ぐため、上記の `node scripts/test-stage-a-local.mjs` を入口にします。子のpnpmも依存の不一致時にはinstallせず停止します。
- 失敗時はそこで停止し、件名・終了コード・所要時間だけのJSON結果を標準出力に出します。子プロセスの生出力や環境変数値を証跡へ入れません。
- 実行用dotenvを見つけた場合は内容を読まずに停止します。元のdotenvを移動・削除せず、機密ファイルを含まない別checkoutを使ってください。
- 本番URLへのsmoke、Vercel deploy、Supabase CLI、既存DBへの接続、認証メール・AIリクエストの送信は含みません。
- Web buildのGoogle Fonts取得など、公開ファイルの読み取り通信は発生し得ます。OSのネットワーク遮断機構ではありません。
  通信が許可されていない環境ではキャッシュだけを使い、取得できない場合はbuild未完了として記録します。
- `--sql-only` はローカルDockerを必要とし、取得済みイメージを `--pull=never --network=none` で使う破棄専用DB試験だけを実行します。
- `PARTIAL_PASS` は選択したソース試験またはSQL試験だけ、`LOCAL_PASS` は全ローカル試験だけの合格です。どちらも本番・実機受入れやバックアップ復旧の合格ではありません。

既存試験の範囲:

| 試験 | 確認できること | 別途必要な確認 |
| --- | --- | --- |
| `test-notebook-sync-runtime.mjs` | 独立した2つの疑似端末での復元・重複防止・写真参照保持、未送信の変更競合保護、旧データのクラウドID継承、保存容量失敗、通信中の追記保持 | 実際の2端末通信、画像の実ダウンロード、ブラウザ保存制限 |
| `test-notebook-sync-safety.mjs` | 全ページ復元、family/本人の結び付け、CAS、再送上限などのソース契約 | 実ネットワーク切断からの復帰 |
| `test-family-role-security.mjs` | viewerの写真upload・更新通知拒否、編集者の署名URL発行を疑似実行 | 画像アップロード、表示、署名URLの更新 |
| family・日記・対象者削除のSQL回帰 | 分離DBでの権限、競合、receipt、再同期による復活防止 | 本番Auth/Storageとの通し試験 |

アクセストークンをブラウザのコンソールへ表示したり、localStorageから取り出したりしません。
Magic Link、認証コード、署名付きURL、service role keyもチャット・Git・スクリーンショットに残しません。
過去の `smoke-notebook-sync.mjs --write` とトークン受け渡しを、本番の確認手順として使わないでください。

## 2. 実機試験の準備

1. 試験専用の所有者Aと招待相手Bを用意します。既存の利用者・削除担当者・一般管理者のアカウントを転用しません。
2. 端末1・端末2、または独立したテスト用ブラウザプロファイルを使います。利用中の通常ブラウザの履歴・サイトデータは消しません。
3. 「動作確認用の親」のような仮名、異なる日付の記録2件、架空の確認リスト、個人情報のないテスト画像1枚を準備します。
4. 対象環境のメールRedirect URL、公開URL、保存先を管理画面で確認します。秘密の値は証跡へ転記しません。
5. 証跡には環境、デプロイSHA、試験日時、端末/OS/ブラウザ、テスト用識別ラベル、期待結果、実結果を記録します。
   私的なAuth IDやメールの対応表が必要な場合は、アクセス制限された台帳に分けます。

## 3. 保存から別端末への復元

画面の表記が変わっている場合は実際のラベルを記録し、似たボタンを推測して押さないでください。

| # | 操作 | 合格条件 |
| --- | --- | --- |
| 1 | 端末1でAの手帳を作り、日記2件・確認リスト1件を保存 | 日付・本文・記録の種類・確認項目が再読込後も一致する |
| 2 | 保存設定からAのメールで本人確認し、メールのリンクを同じテスト環境で開く | ログイン済みになる。リンクやトークンは記録しない |
| 3 | 自動クラウド保存の完了を待つ。必要なら保存設定の保存ボタンを押す | 「この端末とクラウドに保存」など成功状態と件数を確認。通信中・失敗を成功と扱わない |
| 4 | ログイン後にテスト画像を日記へ追加し、保存完了を待つ | 同じ画面の一時プレビューだけでなく、再読込後も画像を開ける |
| 5 | 端末2で同じAのメール確認を行い、同じ家族を選ぶ | クラウドから手帳・日記・確認リスト・画像を読み込める。空の端末内容がクラウドを上書きしない |
| 6 | 日記の件数・日付・本文・種類、確認リスト、画像を端末1と比較 | 全項目が一致。繰返し復元しても件数が増えない |
| 7 | 端末1で記録を追加し、保存後に端末2で読み直す | 新しい記録だけ増え、過去の2件が残る |
| 8 | 端末1・2で同じ項目を別々に変更してから同期 | 競合を表示し、未送信の内容を黙って上書きしない。自動成功と表示しない |
| 9 | 試験プロファイルで通信を一時停止して書き、通信を戻す | 未送信・再試行状態が分かり、復帰後に重複なく保存される |
| 10 | 保存設定の「ダウンロード」でJSON控えを取得 | `cases`・`diaryEntries` 等を確認し、秘密や実データを共有せず保管できる |
| 11 | クラウド完了と端末2での内容一致を確認した後、別の空の試験プロファイルでAにログイン | 手帳・日記・画像が戻る。これは端末内データがない状態の復元試験であり、通常ブラウザのデータ消去は不要 |

JSON控えは写真ファイルの独立したバックアップではありません。写真はクラウドStorage上の保存先を参照します。
また、アプリのクラウド復元と、運営側のDB/Auth/Storageバックアップからの災害復旧は別の試験です。
後者は `COMMERCIAL_OPERATIONS_RUNBOOK.md` のバックアップ・復旧ゲートで確認します。
これらの試験だけで「絶対に記録が消えない」とは案内しません。

## 4. 家族招待・閲覧権限・写真

無料枠の正本は `packages/shared/src/plan.ts` です。現行の `FREE_PLAN_MEMBER_LIMIT = 1` は
**所有者本人に加えて招待1人、合計2人**です。追加の家族枠は受付準備中であり、Plusへの購入誘導を合格条件にしません。

| # | 操作 | 合格条件 |
| --- | --- | --- |
| 1 | Aで `/family` を開き、Bのアドレスと「見るだけ」を選び「招待リンクを作る」 | 権限を選択しなければ作成できない。作成だけでは相手に届かないことが明示される |
| 2 | 管理下の試験アドレスへリンクを渡し、別アドレスで参加を試す | アドレス不一致で参加を拒否。招待の権限や家族は変更されない |
| 3 | 端末2でBとして招待を開いて参加 | 参加前後に「見るだけ」と分かる。Aの手帳・記録・確認リスト・写真が見られる |
| 4 | Bで新規記録、編集、確認項目の更新、写真追加、AI相談、削除を確認 | 操作不可。UIだけでなくAPI/DB拒否はローカル権限回帰で別途検証。実機でトークンを抽出して直接POSTしない |
| 5 | Aで追加の家族を招待しようとする | 無料枠の説明になり、既存の手帳・招待済みBの権限は変わらない |
| 6 | AでBを家族から外し、Bで画面を読み直す | 新しいデータ取得を拒否。既発行の写真署名URLや端末キャッシュは期限まで残り得るため、即時消去したとは案内しない |
| 7 | AでBを「記録・確認リスト・写真を編集」として再招待 | 新しいリンクで参加後、日記・確認リスト・写真を編集できる。親の基本情報と家族管理は変更できない |
| 8 | Bが追加した記録・写真をAで読み直す | 正しく共有され、写真や記録が他の家族へ混ざらない |
| 9 | Bを家族から外して無料枠を空け、Bへの新しい招待を作って未参加のうちに取り消す | 取り消したリンクから参加できない。試験のために無料枠を増やさない |

少なくともiPhone Safari、Android Chrome、報告のあったBraveで狭い画面の保存・復元導線と横はみ出しを確認します。
ブラウザ疑似実行と実機結果は混同せず、未実施の組合せは未実施と記載します。

## 5. 試験データの後片付け

本番テーブルへ直接 `DELETE` を実行しません。対象者名の一致やlocal IDだけを頼りに一括削除しません。

- 手帳・日記だけを消す試験は、所有者AのUIから**対象環境と正確な試験対象**を確認し、2段階確認を経て行います。
  永続receiptとStorage cleanupの完了を確認し、端末2の再読込・再同期で復活しないことも確認します。
- 応答消失や通信エラーは「失敗だから未削除」とも「完了」とも決め付けません。元の処理のreceiptを確認し、
  UIに従って同じ処理を再確認します。DBを手修正して完了扱いにしません。
- アカウントごとの後片付けはA/Bから `/account/delete` で依頼し、`COMMERCIAL_OPERATIONS_RUNBOOK.md` の
  正確なrequest・target・job・manifest、別確認者、AAL2、短時間1回限りの承認、DB/Auth/Storage不在確認に従います。
  この文書やローカル試験の合格だけで本番の削除実行スイッチをONにしません。
- 登録済みの管理者・削除実行者と既存利用者は削除対象外です。清掃未完了の試験アカウントは台帳に残し、
  「完了」と報告しません。

## 6. 不具合が起きたとき

日時・試験ラベル・画面のエラーメッセージ・どこまで保存済みかを記録し、端末の記録を保ったまま停止します。
家族・ログインの不一致、復元の全件取得失敗、容量不足、同期競合は、上書きや履歴消去で回避しません。
`lib/serverSupabase.ts` の `cache: "no-store"` など、保存・復元の新鮮さを守る設定も維持します。
