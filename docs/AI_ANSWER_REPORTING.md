# AI回答の報告と運営確認

2026-09-20。ローカル実装・合成試験の記録。配信・本番受付・審査適合の確認ではない。

## 利用者の操作

Nativeの保存済みAI回答と相談履歴に「このAI回答の問題を報告」を表示する。理由を1つ選び、運営担当者が保存済みの相談文・回答を確認し得る説明へ同意してから送る。画面を開く、回答を生成する、理由を選ぶだけでは送信しない。メール等の別アプリは開かない。

送信はBearer認証付き `POST /api/consult/report`。本文は `{ turnId, reason }` だけ。理由は `unsafe / inappropriate / incorrect / other`。回答本文・相談文・氏名・対象者ID・家族IDは送らず、余分なキーは拒否する。運営への報告は相談の安全性改善のためであり、相談内容への個別回答や緊急対応を約束しない。

サーバーはログインを確認し、保存済み回答→非公開相談スレッドの所有者→対象者→現在の家族所属を検証する。他の家族メンバーの相談、削除済み回答、権限喪失後の相談は受け付けない。読込障害と保存障害は成功表示にしない。受付確認前に通信が途切れた場合は未確認と表示し、再送可能。同じ利用者・回答は最初の理由のまま1件だけ保存する。

## 保存と削除への整合

既存 `audit_logs` に `action = ai_consult_answer_report`、`target_type = ai_consult_turn`、`target_id = turnId` を保存する。IDはサーバー側の決定的UUIDで、既存主キーにより並列再送も重複しない。metadataは理由と説明版 `ai-answer-report-v1-2026-09-20` のみ。利用者IDは `actor_user_id` のみに置き、metadataや本文コピーへ埋め込まない。

既存のアカウント削除では `actor_user_id` がNULLになり、本人の非公開相談スレッド・回答は削除される。報告ログの理由・回答IDは既存監査ログとして残るが、削除された本文をこの機能から復元しない。相談履歴だけを削除した場合も本文コピーは残らない。専用の保管期間・自動削除ジョブは追加していない。既存RLSは監査ログの閲覧を `is_app_admin()` に限定し、通報APIから他の報告一覧は返さない。

## 申請前に残る運用ゲート

専用の通報確認画面・処理状況更新機能は未実装。管理者アクセスの実環境受入もこの作業ではしていない。現在の管理画面で安全に確認できるとは扱わない。担当者、具体的な保存期間、プライバシー説明、最小権限の確認経路と処理記録を整え、合成の報告を受付から対処まで追えることを確認するまで申請条件は未達とする。

確認経路を整えた後の手順:

1. 正式に権限を付与した運営担当者が、上記actionの報告だけを確認する。サービスロールキーを端末・ブラウザへ渡さない。
2. 調査に必要な報告だけで回答IDから保存済みの相談文・回答を参照する。他の相談や家族の記録を一括抽出しない。本文をメール・外部AI・チャットへ転記しない。
3. 誤情報、危険な提案、不適切な表現を確認し、担当者・確認日時・判断・必要な修正と確認結果をアクセス制限された処理記録へ残す。本文削除済みなら「本文削除により調査不能」と記録する。
4. 回答表示やプロンプト等の修正が必要なら、既存のレビュー・試験・本番反映手順で扱う。通報の受付だけで自動削除や外部通知はしない。

本番SQL実行・本番書込・通知送信は未実施。ローカル試験は `node scripts/test-consult-report.mjs`。
