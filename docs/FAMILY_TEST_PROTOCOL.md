# 親のもしもナビ 7日間モニターテスト手順

## 目的

正式公開前に、40〜60代の利用者が説明を受けなくても7日間使えるか、記録が習慣になり得るか、家族共有とFamily Plusに価値を感じるかを確認する。

## モニターへ渡すURL

- 開始ページ: `https://oyano-moshimo-navi.vercel.app/monitor`
- 最終報告: `https://oyano-moshimo-navi.vercel.app/monitor/report`

通常は開始ページだけを渡す。開始ページからテスト開始と最終報告の両方へ進める。

## 期間と必須課題

### 初日

1. スマートフォンで開始ページを開く。
2. 親御さんの呼び名、関係、都道府県、市区町村を入力して、1人分の手帳を作る。モニターでは架空の地域でよい。
3. クラウド保存は任意。端末故障などに備えたい人だけ、手帳の「手帳データの保存先」からメール確認を行う。
4. クラウド保存の有無にかかわらず、7日間は同じスマートフォン・同じブラウザを使い、プライベートブラウズを使わず、履歴・サイトデータを削除しない。

### 7日間

1. 1日1回を目安に、「今日の記録」を7日間で3回以上保存する。1日目の記録も含む。
2. 保存した過去の記録をもう一度見つける。
3. 確認リストを1回試す。
4. 書類の所在メモを1回試す。
5. 家族招待の画面を開き、招待の手順を確認する。実際の招待メール送信は任意。
6. AI相談を1回使う。

### 最終日

1. 開始日を1日目として7日間使い、8日目の0:00以降に手帳の先頭へ出る「お疲れさまでした。最後に回答をお願いします」から専用フォームへ進む。
2. 15〜20分の専用フォームへ回答する。
3. 気になった画面のスクリーンショットを1枚以上、最大3枚添付する。

## 個人情報と機密保持

- 市区町村は架空の地域を入力し、実名、番地以下の詳細住所、病名、電話番号、メールアドレス、暗証番号、マイナンバーは入力しない。
- 呼び名は「お母さん」「テスト父」、記録は架空の内容でよい。
- スクリーンショットに個人情報を写さない。
- 画面で本人が同意した場合に限り、途中経過として、開始日、最終利用日時、記録日数、各機能の到達だけを、名前を含まない端末識別番号で同期する。呼び名、地域、記録本文、写真、相談内容は送らない。最終回答後はクラウドワークス名と紐づける。
- 未公開画面をSNSやブログへ投稿しない。
- 途中経過、回答、スクリーンショットは改善目的だけに使い、モニター終了または提出から6か月後を目安に削除する。本人からクラウドワークスのメッセージで依頼があれば期限前でも削除する。

## 運営が確認すること

- 初日に最初のボタンと手帳作成が分かったか。
- 7日間のうち何日、自分から画面を開いたか。
- 7日間で3日以上記録できたか。何日目に止まったか。
- 記録が保存されたと確信でき、あとから再発見できたか。
- 確認リスト、書類メモ、家族招待の場所と用途が分かったか。
- AI相談へ迷わず進めたか。
- 文字サイズ、ボタン、画面構成に問題がなかったか。
- 今後も使いたいか、家族へ共有したいか。
- 月980円または年9,800円を払う意思があるか。
- 初回登録の完走時間と、一番最初に詰まった画面。
- 端末の自動カウントと自己申告の日記日数の差。
- 記録が止まった場合は何日目か、その日に何があったか。
- 価格提示前の支払上限と、月980円・年9,800円を提示した後の反応の差。

## 回答管理と検収

- 回答一覧: `https://oyano-moshimo-navi.vercel.app/admin/monitor-feedback`
- 名前を含まない途中経過は `audit_logs.action = monitor_progress_synced` に保存し、同じ端末内session IDの行を更新する。
- 回答は `audit_logs.action = monitor_feedback_submitted` に保存する。
- スクショはSupabase Storageの非公開領域に保存し、管理画面だけが期限付きURLを発行する。
- 既存の日次cronで、途中経過は終了予定日から6か月後、回答と画像は最終提出から6か月後を基準に自動削除する。
- 開始ボタンを押した時刻は端末内に保存し、開始日を1日目とした8日目0:00から手帳の先頭へ最終回答案内を固定表示する。日記回数は回答gateにしない。回答送信後は再表示しない。
- 端末内の日記保存回数・日数、初回登録時間、過去記録・確認リスト・書類メモ・家族招待・AI相談・クラウド控えの到達状況を回答payloadへ自動添付し、自己申告と併記する。
- 参加者本人が最終フォームへ、自分のクラウドワークス表示名を入力する。事前の名前登録やモニター番号の発行は行わない。同じ表示名の再送は最新回答で上書きする。
- 報酬条件は最終回答の提出。日記や機能を完了できなかった回答も同額で支払い、未達自体を重要な結果として扱う。
- 検収・支払管理は別のスプレッドシートで、クラウドワークス名、提出日時、支払状態、削除予定日、削除依頼の有無を手動記録する。

## 参加人数に応じた結果の判定

参加人数は固定せず、ランダムに選んだ参加者の回答を探索的なモニターとして扱う。回答者数と各人数を必ず併記し、5人未満しか集まらなかった場合は比率で合否を決めず、個別の迷いと中断理由を中心に判断する。5人以上の回答が集まった場合は、次の暫定比率と定性データを組み合わせる。

- **前進**: 実価格への反応で「月980円を払って使う」または「年払いなら検討する」が回答者の30%以上で、端末の自動カウントで3日以上記録した人が70%以上。
- **再設計**: 3日以上記録した人が70%以上いる一方、上記の前向きな支払意向が30%未満。利用価値はあるが、価格または課金対象の再設計が必要と判断する。
- **立ち止まり**: 記録日数が2日以下の人が70%以上。記録習慣そのものが成立していないため、追加機能より先に記録体験を見直す。

どの基準にも明確に当てはまらない場合は合否を作らず、保存記録の再発見、確認リスト・書類メモ・家族招待手順・AI相談の到達状況、最初の迷い、スクリーンショットの共通点を参加者ごとに並べて、再設計する箇所を定性的に判断する。

## 必ず観察・記録する項目

1. 初回登録の完走時間と、最初に詰まった画面。可能なら初日だけ電話またはLINEで実況してもらう。
2. 日記の端末内自動カウントと自己申告の差。差そのものをデータとして残す。
3. 何日目に記録が止まったか、止まった日に何があったか。
4. 価格提示前の支払上限と、実価格提示後の反応の差。
5. 添付スクリーンショットに写った画面と、複数の参加者に共通する迷い。

## テスト中にやらないこと

- 操作に詰まった直後に正解を教えず、止まった画面と本人の言葉を先に記録する。
- 回答を良く見せるよう誘導しない。
- 医療、法律、税務の判断を断定しない。
- 危機を煽って課金へ誘導しない。
- 実在する親の詳細な健康情報や個人情報を求めない。
