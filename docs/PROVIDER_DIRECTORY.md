# 地域の相談先・広告掲載の運用

## 今回の範囲

AIは相談先の**種類**を案内するだけ。回答内に個社名や広告を入れない。
「地域の相談先を見る」→本人が都道府県・市区町村・分野を選ぶ→一致する公開済み事業者を表示する。
URLへ条件や記録を付けず、絞り込みはブラウザ内のみ。公的窓口へのリンクは検索前から表示する。

- 広告：全カードと区画に「広告」を明記。優先掲載は広告枠内だけ。
- 一般掲載：広告と別区画。契約による順位付けをしない。
- 並び順：広告は sponsorPriority の昇順（省略時0）→名称→ID、一般は名称→IDの固定順。品質・距離の順位ではない。
- 該当なし：他地域や他分野のスポンサーで穴埋めしない。
- 急なとき：既存の危機対応画面は広告なし。相談先画面の先頭からも移動できる。
- 個人情報：プロフィールの自動取得、相談本文の共有、位置情報取得、問い合わせ代行、クリック計測は追加しない。
- 外部サイト：本人のリンク操作だけ。HTTPS、別タブ、参照元非送信。外部サイト側ではIP等を受け取り、独自の方針が適用される。

## 公開事業者の追加

現時点のカタログは**空**。サンプル事業者を本番へ出さない。
既存の sponsor_applications は非公開の申請受付。自動転記・自動承認をしない。
本機能に管理画面・新規DB・成果報酬・課金処理はない。

1. 掲載合意、広告区分、業種別の表示・資格・報酬規制を確認する。医療機関の患者紹介料等は別審査。
2. 正式な公開名称、説明、公式HTTPS URL、対応分野、対応する都道府県と市区町村、情報確認日、開始/終了日時を確認する。
3. apps/web/lib/providerDirectoryCatalog.ts に公開情報だけを登録する。
   担当者・申請メール・電話・予算・申請本文・IP等はコピーしない。自由記述の公開名称/説明にも個人情報を入れない。
4. reviewStatus: approved を明示する。日時は Z または +09:00 等のタイムゾーン必須。
   開始時刻を含み、終了時刻は含まない。終了日時・確認日が不正なら非掲載。
5. cities は、運営が都道府県との所属と対応範囲を確認した市区町村を列挙する。
   県全域対応でも省略・全域ワイルドカードを使わない。政令市は市単位、区限定は完全な区名を登録する。
   入力はNFKC/空白除去後の厳密一致。距離検索・曖昧一致・自治体マスタ照合は行わない。
6. URLに認証情報・クエリ・フラグメント・非標準ポート・IP/localhostを入れない。
   自動検証は安全性・実在性を保証しない。公式サイトであること、転送先、追跡リンクでないことも人が確認する。
7. 最初の実掲載時は空カタログを検証するテストを、承認済み公開項目の検証へ更新する。
   private情報・合成事業者なしをレビューし、ローカルテスト→明示的な本番反映承認を経る。

## 更新・停止と限界

- draft / paused、不適合、重複ID、不正URL、期間外の行はサーバーから公開しない。
- ページはリクエストごとに公開条件を確認。開いた画面でも期限時刻・定期・再表示・通常リンク操作で再確認する。
- カタログの変更/承認取消はコード反映とページ再取得が必要。既に開いた画面の情報を即時回収する管理APIはない。
- オフライン・ブラウザ休止・端末時刻の変更や既に外部へ開いたページまで制御するものではない。
- より厳密な即時停止や大量登録が必要になったら、公開専用テーブルと審査履歴・運営権限を別途設計する。
- 紹介件数・問い合わせ・成約を保証せず、AIが最適・最寄りと認定したかのような営業表現を使わない。
